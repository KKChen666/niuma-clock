# 旧版踩坑清单（重构时别重犯）

旧版是 1200+ 行单文件、手写 DOM + `innerHTML` 重绘。下面这些坑大多由「手动操作 DOM」引起，换 React 受控组件后会自动消失；**标「⚠️ 口径」的是业务规则，重构时必须保留或显式决定改掉。**

## 一、这次迁移顺手修掉的三个真 bug（旧版已修）

1. **inline `onclick` 与同名 `id` 冲突**
   `<button id="tpToggle" onclick="tpToggle()">` —— inline handler 的作用域链里，`tpToggle` 被解析成 **DOM 元素**而不是函数，报 `tpToggle is not a function`，时间面板根本打不开。
   → 已改成 `addEventListener('click', tpToggle)`。React 用 `onClick` 没有这个作用域问题。

2. **`innerHTML` 重建节点 + `contains()` 误判外部点击**
   点时分格 → `tpRenderCols()` 用 `innerHTML` 重建整列 → 事件冒泡到 `document` 时 `e.target` 已从 DOM 分离 → `tpRange.contains(e.target)` 返回 false → 被当成「点击外部」把面板关掉。表现为选完开始时间，面板突然消失但内部状态还切到了「结束时间」。
   → 已改用 `e.composedPath().includes(range)`（事件路径快照）。
   → React 里根本没有这种「先移除再判断祖先」的时序问题；AntD `TimePicker.RangePicker` 直接替代这整套手写面板。

3. **浮层与容器的层级判断**
   第一版把「点击外部关闭」写成只看 `tpRange`，没考虑 `tpPanel` 的位置关系，点「确定」也会被误关。现已统一用事件路径判断，一次覆盖容器内所有后代。

## 二、⚠️ 业务口径类（必须保留）

4. **农历表 1909 年条目**：`LunarInfo[9]` 必须是 `0x055b2`（闰二月，384 天）。旧版曾误抄成 `0x055b0`（平年 355 天），导致 **1909 之后所有日期整体偏移 29 天**。已修，测试里钉了 2024/2025/2026 春节 + 2026-11-03 九月廿五四个锚点。搬表时别手抄，直接从 `src/logic/lunar.js` 复制。

5. **手动时长 vs 自动时长互斥**：旧版把这条规则散在 `document.addEventListener('input')` 里——手动值非空就清空起止，起止齐全就清空手动值。重构时务必收敛成**单一 state + 明确优先级**（见 `01-重构规格.md` 第三节第 3 条），否则两个字段互相触发又会绕回去。

6. **结束计时不写 `duration`**：只回填 `date/start/end`。因为表单规则是「手动时长非空 → 清空起止」，硬写 duration 会导致用户一改时间就被清空。让表单按起止自动算即可。

7. **计时只存绝对时间戳** `{startAt, startDate, startHM}`，不存「已过秒数」、不做逐秒累加。刷新、关页、切 Tab 都不丢；多标签靠 `storage` 事件同步。**React 里也要监听 `storage`**，否则两个标签页会各自显示不同计时。

8. **24h 环上 1 小时只有 15°**，只画一段增长的弧，半小时加班肉眼几乎看不出在动。旧版补了两层才「直观」：内圈 1 小时/圈的分钟环 + 中央跳动的秒表。重构别只留大圆环。

9. **计时中隐藏红针**：第一版红针斜穿过中央秒表小字、红点还和琥珀弧末端圆点重叠，糊成一团。计时中由琥珀弧末端的圆点指示「现在」。

10. **单次计时 > 24h 算不准**：`start/end` 只有 `HH:mm` 没有日期，超过一天会绕回。旧版列为已知边界，未修。重构若要支持，得改数据契约为 ISO 时间戳并写迁移。

## 三、UI / 工具类

11. **LeiBox 按压按钮的双层 span**：旧版「保存」按钮套了 `.button-outer/.button-inner` 两层，代码里 3 处 `saveBtn.textContent='保存'` 会直接把双层结构清空。已改成写内层 `#saveLabel`。React 里直接 `{editing ? '更新' : '保存'}`，别碰 DOM。

12. **无头 Chrome 最小窗口宽度**：`--window-size=390,844` 实际 `innerWidth` 是 **504**（Chrome 有最小宽度限制），截图右侧被裁是假象，不是布局溢出。判断溢出要看 `document.documentElement.scrollWidth` 与 `innerWidth` 的差值，别信截图。

13. **`fmtDur` 的 60 分进位缺陷 —— 本次已修**：`fmtDur(1.999)` 旧版会算出 `1小时60分`（`Math.round((h-hh)*60)` 可能等于 60）。现在 `src/logic/time.js` 先算 `Math.round(|h|*60)` 再拆时/分，得到「2小时」，并对极小值兜底返回 `0`。日常分钟级数据显示不变，回归测试钉了 `4.25h → 4小时15分` 与 `1.999h → 2小时` 两组。

14. **年「出勤率」命名误导 —— 本次已改**：实际是「全年加班天数 ÷ 365 × 100」。UI 现在叫「加班天数占比」；`yearSummary()` 返回 `daysRatio`，`attendanceRate` 保留同值别名并标了 `@deprecated`，避免外部旧调用断裂。

15. **`note` 字段预留未用 —— 本次已启用**：表单可填、当天明细可见、编辑可改、JSON 备份完整保留。**CSV 仍固定 6 列不加备注**，兼容旧版导出的表格模板；`recentContents()` 另给表单提供最近常用内容候选。

16. **antd 5 `Calendar.cellRender` 是「追加」不是「替换」（实测翻车，最终用 `fullCellRender` 回归官方组件）**：按 5.x 文档用 `cellRender` 自定义月历内容时，antd 仍会自己渲染一份日期数字，自定义内容被追加在它下面 → 一格出现两个日期、农历和相邻格文字挤成一团；`.ant-picker-cell-selected` 的蓝底又只盖住默认数字那 24px，看起来像「选中块只有上半格」。
    - 第一版修法是**自绘 7 列 CSS Grid**（`monthGrid()` 纯函数，按 `(offset + daysInMonth)/7` 算实际周数，去掉硬凑的第 6 行），能跑但等于绕开官方组件。
    - 后续按组件总览重做时查了源码：`node_modules/antd/es/calendar/generateCalendar.js` 里 `cellRender` 被包进 `.ant-picker-calendar-date-content` 追加，而 `fullCellRender` 在 `rc-picker/es/PickerPanel/PanelBody.js` 里是 `return fullCellRender(...)` —— **直接替换整个 `<td>` 内容**，不会再生成默认日期数字。
    - 最终方案：`Calendar` + `fullCellRender` + `headerRender`（内嵌 `DatePicker picker="month"`）+ `onSelect(date, info)` 判 `info.source === 'date'`；选中 / 今天 / 补位日靠 `<td>` 上的官方类名 `.ant-picker-cell-selected` / `-today` / `-in-view` 驱动 CSS。`monthGrid()` 纯函数与回归测试保留做几何兜底。
    - `npm run check:ui` 已静态断言：42 格、每格仅 1 个日期数字、`cell-inner` 残留 0、表头周一开头且中文。

17. **`TimePicker.RangePicker` 的 `minuteStep` 别乱设（本次实测翻车，已修）**：`EntryForm.jsx` 里写了 `minuteStep={5}`，分钟列就只剩 `00/05/10/…/55` 共 12 档，用户根本选不了 `23:07`、`01:23` 这种真实下班时间。antd 默认步长本来就是 1，显式写 `minuteStep={1}` 才清楚。已用无头 Chrome 点开面板实测：小时列 24 项、分钟列 **60 项 00–59 连续无跳档**，并把这条断言固化进 `npm run check:single`（注入脚本点开 RangePicker → 读 `.ant-picker-time-panel-column` 第 2 列 → 比对 60 项）。改完记得**重新 `npm run build:single`**，否则发出去的单文件还是旧版。

## 五、一条经验

旧版这几个 bug（同名 id、innerHTML 重建、浮层层级、双字段互相触发）本质都是**「手动同步 DOM 状态」**的代价。用 React + AntD 重构时，把状态收在组件里、让 UI 从状态渲染，比修补这些边界值划算得多。`src/logic/` 已经把不依赖 DOM 的部分全剥干净了，剩下的交给组件就好。
